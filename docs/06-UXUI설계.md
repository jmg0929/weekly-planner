# 06. UX/UI 설계

## 1. 디자인 원칙

| # | 원칙 | 적용 예 |
|---|---|---|
| P1 | **일정이 주인공** — 장식보다 내용 | 그라데이션·그림자 최소, 카드 = 회색 바탕 + 카테고리 색 살짝 |
| P2 | **흑백 + 의미 있는 색만** | 강조색 = 검정(다크 모드는 흰색). 빨강은 현재시각선·일요일·공휴일, 파랑은 토요일 |
| P3 | **단어 하나로 충분** | `표시` `편집` `백업 · 복원` `3일 전` `n / 전체` — 설명 문장 지양 |
| P4 | **한 손 · 엄지 우선** | 아래 떠 있는 탭 바, 아래에서 올라오는 시트, 좌우 스와이프 |
| P5 | **빼는 것도 설계** | 완료 체크·지난 시간 흐림·카드 이모지·표시 스위치를 실제 사용 후 제거 |
| P6 | **로컬처럼 즉시** | 저장 즉시 반영, 동기화는 뒤에서. 오프라인은 오류가 아님 |

### 2.3 타이포그래피

글꼴: **Pretendard Variable** 단일 (`'Pretendard Variable', Pretendard, -apple-system, 'Apple SD Gothic Neo', 'Segoe UI', sans-serif`), 기본 자간 `-0.01em`, 숫자는 `.tnum`(tabular-nums), 한글 `word-break: keep-all`.

| 역할 | 크기 / 굵기 | 위치 |
|---|---|---|
| 일정 시트 제목 입력 | 24px / 800 | `.ev-title` |
| OTP 숫자 | 24px / 800 | `.otp-boxes span` |
| 상단 월 제목 | 22px / 800, 자간 -0.035em | `.title .month` |
| 요일 날짜 숫자 | 18px / 800 | `.dh .dnum` |
| 시트 제목 · 미리보기 제목 | 18px / 800 | `.sheet h2`, `.peek-title` |
| 입력 | 15.5~16px / 600~700 | `.field input`, `.ev-in` (OTP 입력은 16px — iOS 확대 방지) |
| 메뉴 항목 | 15px / 700 | `.mtx b` |
| 주간 목록 일정 | 12px / 700 | `.arow .at` |
| 일정 카드 제목 | 11px / 700 | `.evt .et` |
| 시간 눈금 · 요일 | 10.5px | `.gutter`, `.dh .dow` |
| 카드 태그명 · 짧은 카드 | 9.5px / 700 | `.etag`, `.evt.short .et` |
| 하루 보기 장소·시간 | 9px | `.eloc`, `.etime` |
| 공휴일 이름 (헤더) | 8.5px | `.hname` |

> 11px 미만 글자가 일부 있음 → 자체 점검에서 **최소 11px** 백로그로 등록.

## 4. UX 의사결정 기록 (Decision Log)

> 형식: 문제 → 선택지 → 결정 → 이유. 버전은 서비스워커 캐시 번호(`planner-vN`).

| ID | 문제 | 선택지 | 결정 | 이유 · 근거 |
|---|---|---|---|---|
| D-01 | 겹치는 일정이 좁은 열에서 읽히지 않음 | ① 좌우로 쪼개기 ② 묶음 카드 | ② 묶음 카드 + 목록 시트 (v7) | 7열에서 쪼개면 글자가 안 보임. 개수 배지와 색 점으로 존재만 알림 |
| D-02 | 7열에서 긴 제목이 잘림 | ① 글자 축소 ② 하루 크게 보기 | ② 요일 탭 → 하루 보기 (v12) | 정보 밀도는 유지하고, 필요할 때만 확대 |
| D-03 | 이전/다음 버튼이 상단을 복잡하게 함 | ① 버튼 유지 ② 스와이프 | ② 좌우 스와이프 (v16) | 세로 스크롤과 구분: 가로 55px↑ · 세로의 1.6배↑ · 600ms 이내 |
| D-04 | 지난 시간 흐리게 표시 | 유지 / 제거 | 제거 (v23) | 사용자: 지난 일정도 또렷하게 보고 싶음 |
| D-05 | 레퍼런스(태블릿 캘린더) 스타일 적용 | 그라데이션·카드 헤더 유지 / 미니멀 | 미니멀 (v25 → v26) | 그라데이션 거부. 시간 눈금 `07`, 블록엔 제목만, 오늘은 알약 하나 |
| D-06 | 일정 탭 즉시 편집 시트 → 실수로 편집 진입 | ① 즉시 편집 ② 미리보기 후 편집 | ② 미리보기 카드 → `편집` (v25) | "보기"가 "고치기"보다 훨씬 잦음 |

| D-08 | 3일 보기 활용도 낮음 | 3일 유지 / 5일로 | 4 → 5 → 7 순환 (v30) | 평일 5일 보기 수요. 저장된 `3`은 `4`로 이전 |

| D-37 | 마지막 카테고리 ✕를 눌러도 반응 없음 | 그대로 / **비활성 표시** | 하나만 남으면 ✕를 흐리게 · 누를 수 없게 (v45) | "삭제가 안 된다"는 오해. 상태를 눈에 보이게 |

## 6. 접근성

### 6.1 구현된 것

| 항목 | 내용 |
|---|---|
| 아이콘 버튼 이름 | `aria-label`: 일정 추가, 메뉴, 보기 모드 바꾸기, 주간으로 돌아가기, 날짜로 이동, 시간표/주간 목록 보기, 이전/다음 달, 수정, 삭제, 닫기, 새 카테고리, 인증번호 6자리 등 |
| 대화상자 | 시트·미리보기에 `role="dialog" aria-modal="true"`, 미리보기 `aria-labelledby` |
| 토글 상태 | 필터 칩 `aria-pressed` |
| 장식 요소 숨김 | OTP 가짜 칸 `aria-hidden="true"` (실제 입력은 하나) |
| 탭 바 | `<nav aria-label="보기 전환">` |

| 움직임 줄이기 · 다크 모드 | 시스템 설정 반영 |

| 항목 | 현재 | 개선 방향 |

## 7. 마이크로카피 가이드

| 규칙 | 좋은 예 (현재 앱) | 피할 것 |
|---|---|---|
| 라벨은 **단어 하나** | `표시` `편집` `동기화` `백업 · 복원` | "카테고리를 탭해서 보이기/숨기기를 바꿀 수 있어요" |
| 상태는 짧은 명사·시간 | `방금` `3분 전` `오프라인` `동기화 중` `다시 로그인` | "마지막 동기화: 2026-11-03 21:30:12" |
| 수량은 기호로 | `3 / 5`, `기록 없음` | "5개 중 3개 표시 중" |
| 구분자는 가운뎃점 | `이미 가입된 이메일 · 로그인을 누르세요`, `장소 · 기간 · 색` | 괄호·줄바꿈 남용 |
| 오류는 원인 + 할 일 | `인증번호가 틀렸거나 만료됐어요`, `시간 초과 · 다시 보내기를 누르세요` | "오류가 발생했습니다" |
| 말투 | 해요체, 짧게 (`틀려요`, `달라요`) | 합니다체·명령조 혼용 |
| 확인 대화상자 | 결과를 말함: "로그아웃할까요? 이 기기의 일정은 그대로 남아요." · "취소하면 로그인하지 않아요." | "계속하시겠습니까?" |
| 보안 문구 | 계정 유무를 드러내지 않는 같은 문구 (`이메일 또는 비밀번호가 틀려요`) | "존재하지 않는 계정입니다" |

**정리 대상 (일관성)**: 백업 시트 안내 문단(`bk-note`, `bk-cap`)과 일정 시트 보조 설명(`(선택 · 비우면 계속 반복)`, `(카테고리 색이 기본 · 바꾸면 이 일정만)`)은 아직 문장형. 일정 폼 오류는 마침표가 있고(`제목을 입력해 주세요.`) 계정 오류는 없음 → 한 규칙으로 통일 필요.
