| 항목 | 규칙 |
|---|---|

| 사용자용 내역 | [`updates/README.md`](../updates/README.md) (날짜별, 쉬운 말투) |

## 4. 회고

### 4.1 잘한 점 (Keep)

| 항목 | 내용 |
|---|---|
| 로컬 우선 설계 | 서버를 나중에 붙였는데도 기존 기능 변경이 거의 없었음 (`save()` 끝에 `onLocalChange` 한 줄 연결) |
| 서버 쪽에서 강제 | 권한(RLS)과 최신 우선(트리거)을 DB에 둬서, 클라이언트 키가 공개돼도 안전한 구조 |
| 외부 입력 불신 | 백업 파일용으로 만든 정제 함수를 서버 데이터에도 재사용 → 동기화 추가 시 XSS 표면이 늘지 않음 |
| 공격 시나리오를 테스트로 | "공격자 링크로 열면 데이터 요청 0건"처럼 보안 요구를 **측정 가능한 기대 결과**로 표현 |
| 배포 자동화 | 캐시 버전 올리기를 잊는 실수를 스크립트로 제거 (v27 이후 번호가 정확히 연속) |
| 사용자 문서 | 기능마다 `updates/README.md`에 쉬운 말로 기록 — 동기화 상태 단어 표까지 |

### 4.2 트레이드오프 (의식적으로 선택한 것)

| 선택 | 얻은 것 | 포기한 것 |
|---|---|---|
| 단일 `index.html`, 빌드 없음 | 즉시 수정 · 배포, 의존성 0 | 모듈화 · 타입 검사 · 단위 테스트 도구 |
| 강화 보안 세트 되돌림 | 가벼운 가입 · 적은 운영 부담 | CAPTCHA · 탈퇴 · 저장 한도 (수용 위험으로 문서화) |
| 항목 단위 LWW | 단순 · 예측 가능 | 같은 일정의 필드 단위 병합 |
| `localStorage` 토큰 | 정적 호스팅에서 로그인 유지 | HttpOnly 쿠키 수준의 XSS 내성 |
| 이메일 + 비밀번호 (Google 로그인 보류) | OAuth 설정 · 리디렉션 문제 회피 | 비밀번호 없는 편의 |
| 기능 제거 (완료 체크 등) | 단순한 화면 | 일부 사용 시나리오 |

| 시안 먼저, 문서는 확정 후 | 할 일 화면은 시안 1(카테고리 카드) → 요일별 → 6개 제한 · 확대 보기 → 달력 표시 → 카테고리 분리 순으로 바뀜. 시안마다 문서를 고치다 버리는 일이 생겨, **문서는 배포 승인(ㄱㄱ) 뒤에 한 번에 쓰기**로 규칙을 바꿈 |
| 많아질 때를 먼저 시험 | "할 일이 많아지면?" 시험에서 줄 높이 폭증과 동기화 1000줄 한계를 발견 → 화면은 v45, 동기화는 v46에서 해결. 시험 도중 동기화가 반복되는 것도 발견했는데, 원인이 미리보기 창의 화면 복귀 신호라는 걸 추적으로 확인하고 앱 쪽 낭비(B-16)만 고침 |

### 4.3b v47~v51에서 배운 점

| 항목 | 내용 |
|---|---|
| 실기기만의 차이 | 미리보기(크롬)에선 체크가 가운데였는데 아이폰 Safari는 `button` 기본 안쪽 여백 때문에 밀림. "여전히 안 들어간다"는 피드백 뒤에야 원인을 찾음 → 버튼 기본 스타일은 처음부터 0으로 |
| 눈대중 대신 측정 | 줄 위치를 "가운데 같다"로 넘기지 않고 글자 잉크 중심과 줄 중심을 계산해 비교 → 0.5px 차이 발견 |
| 누르는 동안 화면 고정 | 체크 즉시 정렬은 논리적으로 맞지만 손가락 밑 대상이 바뀜. "누르는 중엔 고정, 끝나면 정리 + 움직임 보여 주기"를 터치 UI 원칙으로 |
| 데이터와 표시 분리 | 요일 데이터(월=0)를 그대로 두고 표시 순서만 바꿔, 주 시작 변경이 데이터 이전 없이 끝남. `ord`도 `data` jsonb라 스키마 변경 없음 |
| 입력 장치의 물리 | 트랙패드는 손을 떼도 관성 신호가 이어짐 → "한 번 밀기 = 한 칸"은 잠금이 계속 연장됨. 스크롤처럼 "민 거리"로 바꿔 해결 |
| 가려진 창의 타이머 | 미리보기 창이 가려지면 타이머가 늦춰져 시간 테스트가 실패처럼 보임 → 시간 함수를 바꿔 끼워 기다리지 않고 검증 |
| 문서는 모아서 | v47~v51을 배포마다 문서화하지 않고 사용자 요청 때 한 번에 반영 — 배포 속도는 유지하고 문서는 `updates/README.md`로 추적 |
